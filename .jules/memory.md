These are injected into `mesh.advertise_capabilities()` and used by `mesh.py` to filter incoming `command_request` broadcasts targeting specific hardware capabilities or topology tags.
* The `polyphony test` command delegates to `scripts/test_wrapper.py` to ensure local tests execute serially by acquiring the machine-wide `/tmp/polyphony_build.lock`.
* The `.flake8` configuration excludes `.venv` directory to prevent linting virtual environment dependencies.
* The automated workflows 'auto-merge-staging.yml' and 'workflow-review.yml' are configured to use the 'git merge -X theirs --no-edit' strategy to automatically resolve merge conflicts in favor of the incoming PR branch.
* Agents can append and audit incremental changesets using the FastMCP tools `save_revision(key, diff)` and `get_revisions(key)` exposed in `src/liminal_bridge/server.py`.
* A comprehensive usage guide for the Hybrid WASM LLM Engine is located at `docs/hybrid-wasm-llm.md`, and linked in the README, covering instructions for building the WASM engine, distributing weights, planning pipeline topologies, and routing mesh nodes.
* The script `scripts/prepare_mesh.sh` is a shell wrapper that activates the virtual environment and runs `scripts/prepare_model_mesh.py`, the unified CLI tool for preparing the Hybrid WASM LLM Engine deployment. It accepts a `.gguf` file to calculate Pipeline Parallelism topology (via `gguf_sharder.py`) and slice/distribute model weights (via `gguf_distributor.py`).
* For GitHub Actions handling AI PR reviews on forks (e.g., `pull_request_target`), the project strictly uses 'Diff-Only Ingestion'. Never use `allow-unsafe-pr-checkout: true`. Workflows must check out the trusted base repository and use the GitHub CLI (`gh pr diff`) to ingest untrusted changes strictly as raw text patches, preventing code execution vulnerabilities and protecting repository secrets.
* The local test and push queue locking mechanism (`scripts/lock_utils.py`) uses `os.open` with `O_CREAT | O_EXCL` for atomic file creation and `os.kill(pid, 0)` for stale PID liveness checking.
* The custom AST-based isolate validator script `scripts/check_isolates.py` (tested by `tests/test_isolate_lint.py`) statically enforces the 'No Inline Async' rule by verifying no `async def`, `await` expressions, or blocking network/database library imports exist within `BaseIsolate` implementations.
* BLE communication (`broadcast_micro`) in Keystone Polyphony enables proximity-based, out-of-band communication for bridging air-gapped networks and utilizing physical presence as part of security parameters.
* Encrypted mesh messages are transmitted as JSON objects containing `e` (base64-encoded ciphertext), `s` (Ed25519 signature of the ciphertext), and `p` (sender's public key hex), which sidecars broadcast without inspection. Unencrypted messages are no longer supported.
* In `src/liminal_bridge/server.py`, the `run_inference` command is handled automatically by setting the node status to busy, executing the prompt via the local `Architect`, and immediately streaming the text result back to the swarm via `share_thought()` to close the context sync loop.
* The `identity_registry` CRDT maps node IDs to their respective public keys for decentralized cryptographic verification.
* The `ModelDistributor` class in `src/liminal_bridge/gguf_distributor.py` handles chunking large `.gguf` model files into smaller binary pieces (e.g., 50MB), generating a JSON assembly manifest of SHA-256 hashes, and outputting a `seed_model_to_pollen.sh` bash script with `pln seed` commands for Pollen P2P distribution.
* The repository includes `pollen_comparison.md`, documenting the architectural relationship, parallelism mapping (inspired by NVIDIA Megatron), and integration strategy for building a Hybrid WASM LLM engine combining Keystone Polyphony and Pollen.
* Python code formatting is enforced using `black`. When fixing formatting issues reported by `scripts/lint.sh`, target specific directories like `black src/ tests/ scripts/` rather than `black .` to avoid inadvertently formatting third-party files or submodules.
* When mocking API keys in tests (e.g., `Architect(api_key="...")`), use explicit dummy values (like appending `-dummy`) to prevent triggering security/secret scanners, while still preserving identifying prefixes if required by detection logic (e.g., `sk-proj-dummy`, `AIzaSyD-dummykey`).
* LiminalMesh implements multi-modal transport switching in its broadcast method: high urgency or macro-level updates (distance > 5.0m) route via `broadcast_macro` (using `aiomqtt` for MQTT, configured via `MQTT_HOST` and `MQTT_PORT`), micro-level updates (distance < 1.0m) use `broadcast_micro` (using `bleak` and `bless` for BLE, configured via `BLE_ENABLED`), and defaults to Hyperswarm (DHT) via sidecar. Distance is evaluated using 'self.peer_distances' in meters.
* `LiminalMesh` uses a storage abstraction layer (`BaseStorageProvider` in `src/liminal_bridge/storage.py`) that supports `SQLiteStorageProvider`, `RedisStorageProvider`, and `PostgresStorageProvider`. The provider is injected via the `storage_provider` parameter, replacing the legacy `db_path` argument.
* Running unit tests locally requires setting the python path appropriately, often `PYTHONPATH=.:src` (e.g., `PYTHONPATH=.:src pytest tests/`), to ensure test imports using 'src.liminal_bridge' and 'liminal_bridge' both resolve correctly and prevent 'ModuleNotFoundError'.
* The `polyphony` CLI in `src/liminal_bridge/server.py` allows configuring the storage backend via `--storage-backend` (choices: sqlite, redis, postgres) and `--storage-url` arguments, or their corresponding `STORAGE_BACKEND` and `STORAGE_URL` environment variables.
* The single-threaded loop executor `TpcExecutor` (`src/runtime/tpc_executor.py`) manages core affinity pinning (via `os.sched_setaffinity` on Linux) with graceful fallback logging for non-Linux platform environments.
* The baseline setup script `setup-ensemble.sh` securely generates a dynamic random key for the swarm on interactive fallback or non-interactive headless setup to enforce robust out-of-the-box security without hardcoded defaults.
* The `BoundedMailbox` class (`src/core/mailbox.py`) implements bounded thread-safe message queues wrapping standard `queue.Queue` with four load-shedding policies: `FAIL_FAST`, `DROP_OLDEST`, `DROP_NEWEST`, and `BACKPRESSURE_WAIT`.
* The `Register` CRDT (formerly LWWRegister in `src/liminal_bridge/crdt.py`) accepts a pluggable `resolve(a, b)` callback during `merge` to deterministically break concurrency ties using domain policies (like ensemble verification) instead of relying on an LLM oracle or hardcoded LWW logic.
* The `Pulse` module actively monitors baton health, broadcasting a forced `baton_release` if a baton owner lacks thought activity for over 5 minutes.
* Audit events (e.g., task completions) are immutably logged to an `audit_log` CRDT via `LiminalMesh.log_audit_event`.
* The `Architect` class routes the `google` provider directly through the local Ollama interface (`_consult_ollama`), avoiding the need for the `google-generativeai` SDK.
* Shell scripts should avoid hardcoding `python3` or `python` as it can trigger the empty Microsoft Store execution alias on Windows/MSYS. Dynamically detect the valid executable using `command -v` and verify it runs successfully (e.g., `python -c 'import sys'`). Always ensure the virtual environment (`.venv`) is activated prior to this detection.
* The `scripts/build_wasm_llm.sh` script automates the compilation of a WASM LLM inference engine by downloading Emscripten and building `tangledgroup/llama-cpp-wasm` into the `dist/wasm_llm/` directory. It uses `uname -s` to robustly detect Windows/MINGW environments and injects Git environment variables (`GIT_CONFIG_COUNT` etc.) to enforce `core.longpaths=true` to prevent 'Filename too long' clone errors for deep nested submodules.
* A generic Python context manager `polyphony_file_lock` (in `src/core/lock_manager.py`) is used by agent tools to intercept file modifications. It interacts with `LiminalMesh` and raises `FileLockedError` if the file is locked, facilitating conflict backpressure.
* The project has implemented a Hybrid WASM LLM Engine that layers Keystone Polyphony's agent orchestration and context sharing over Pollen's distributed WASM compute fabric, tracked and documented via TODO.md.
* GitHub Actions workflows should pin runners to `ubuntu-24.04` to avoid Ubuntu 26 migration deprecations, and utilize the `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true` environment variable to suppress Node.js 20 deprecation warnings on older actions like `checkout@v4`.
* The project aims to implement finer-grained Sequence CRDTs (e.g., natively in `LiminalMesh` or via libraries like `y-py` or `Automerge`) for text editing to enable true simultaneous collaboration in shared scratch spaces, context windows, and code files, eventually bypassing coarse file-level Baton locks.
* The `polyphony land` command provides a Python-native, serialized local test and push queue that automatically rebases against `origin/main`, acquires a machine-wide lock (`/tmp/polyphony_build.lock`), runs tests, and pushes to origin to prevent concurrent agent CPU thrashing and push races across multiple git worktrees.
* Unit tests must run completely offline (air-gapped) by heavily mocking external networking infrastructure (like Pollen CLI commands, QUIC requests, or Node.js sidecar execution) to validate python logic without attempting peer-to-peer connections.
* Keystone Polyphony features a Project Tina-inspired Thread-Per-Core (TPC) and Isolate architecture. Isolates subclass `BaseIsolate` (`src/core/isolate.py`) and must handle messages synchronously (`handle_message(self, msg) -> list[BaseEffect]`), outputting declarative side effects (`BaseEffect` subclasses in `src/core/effects.py`).
* A Deterministic Simulation Testbed (DST) is supported via the `DeterministicScheduler` (`src/runtime/deterministic_scheduler.py`), enabling offline deterministic execution of swarm messaging loops over a virtual logical clock with pseudo-random seed-based delays.
* The project utilizes a `RevisionLog` CRDT (`src/liminal_bridge/crdt.py`) that maintains a grow-only set of `(timestamp, author, revision_id, unified_diff_text)` tuples to track a granular, decentralized history of code changesets.
* The `polyphony` CLI supports granular file-level locking (batons) via the `polyphony baton acquire <filepath>` and `polyphony baton release <filepath>` commands, implemented in `scripts/baton.py`.
* The legacy insecure default swarm key (`KEYSTONE-POLYPHONY-UPSTREAM`) has been completely removed from the repository. In `server.py`, if `SWARM_KEY` is not set, a cryptographically secure 64-character hexadecimal session key is dynamically generated in-memory, printing a warning to stderr.
* The `GGUFSharder` class in `src/liminal_bridge/gguf_sharder.py` dynamically calculates transformer layers in a GGUF file to divide them into pipeline stages. It is used by `Architect.plan_pipeline_parallelism()` to orchestrate Pipeline Parallelism by assigning `--prop pipeline_stage=X` tags to Pollen nodes.

* The Pollen WASM integration utilizes the `extism/go-pdk` in `src/pollen_integration/wasm_wrapper.go` to receive JSON inference payloads from the Pollen host and stream generated text back from the compiled `llama.cpp` engine.

It writes raw cache blobs to Pollen (`pln seed`) and broadcasts the resulting Pollen blob hash via a Keystone `ORSet` CRDT for conflict-free assembly.
* The `Architect` class in `src/liminal_bridge/architect.py` supports a `pollen_mesh` inference provider, triggered when the `DUCKY_MODEL` environment variable starts with `pollen:`. It reads the `POLLEN_GATEWAY_URL` environment variable (defaulting to `http://localhost:3000`) and uses `aiohttp` to send OpenAI-compatible JSON payloads directly to a Pollen gateway.
* Agents can delegate cognitive tasks using `LiminalMesh.delegate_inference_task()`, which broadcasts a `run_inference` command targeted specifically at nodes advertising `pollen_compute` capabilities.
* When executing the Liminal Bridge server (e.g., in Docker or CI workflows), use the module execution format (`python -m src.liminal_bridge.server`) and ensure `PYTHONPATH` is set (e.g., `PYTHONPATH=/app`) to avoid `ImportError` issues with relative imports.
* Large files can be flagged for decomposition via `polyphony issue flag-megafile <filepath>` (in `scripts/flag_megafile.py`). This script automatically queues a refactor task in the `swarm_backlog` if a file exceeds 1,000 lines or 50KB.
